# Agent Dash: retention, logging and user content

- **Agent posts are user content.** Widget titles, widget state (`state_json`), events, and agent names, descriptions and heartbeats are free-form text that agents write on the user's behalf. The server treats them as the user's data: it shows them only to the owner, never sends them to another agent, and never acts on them. The secret scanner (`scrub.ts`) only redacts key, token and card shapes; it is not a content filter and does not make a post safe or private.
- **Size cap.** One widget state or event is at most `MAX_CONTENT_BYTES` (8 KiB) as stored JSON after scrubbing, batch ops included; the request body caps (8 KiB single, 64 KiB batch) still apply on top.
- **Retention (30 days, `RETENTION_DAYS`).** The hourly alarm, and every owner view, prune: events and audit entries older than 30 days; widgets (title, `state_json`, their events) not updated for 30 days; agents of any status not seen for 30 days, together with all their widgets, events and idempotency records (their id and token hash are tombstoned so the token answers 410 stop). Used or expired enrollment codes and expired idempotency records go too.
- **Deletion.** Deleting an agent (unenrolling it) removes its row, widgets, `state_json`, events and idempotency records at once. Deleting the dashboard removes codes, agents, widgets, events and idempotency records. Tombstones (scope plus agent id, `agent/key`, or token hash, never content) and the audit log (event name, agent id, time) remain; audit entries age out after 30 days.
- **Logging.** `wrangler.toml` turns Workers Logs off (`[observability] enabled = false`, `head_sampling_rate = 0`) and the Worker has no `console` calls, so no request URL, query string, header or body is logged. There is no `[env.*]` override, so this is the production config; `test/api.test.ts` checks it.
