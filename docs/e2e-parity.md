# E2E parity: Electron suite → Tauri/Rust integration tests (phase 5)

The Electron app (`apps/desktop`, Electron) and its Playwright suite (`e2e/*.spec.ts`) are being deleted in the
forced cutover (phase 6). This file is the parity reference that survives the delete: every Electron E2E scenario,
what it proves, and its Rust equivalent under `crates/qrtz-app/tests/` (driven through `build_app` + the IPC router +
a real helper child process + local mock LLM/HTTP servers, condition-based waits only).

Snapshot of the Electron suite taken at `c6723c4` (2026-10-17 10:07 PT): 15 spec files, 41 Playwright scenarios
(the theme spec runs twice, dark and light), plus the vitest flow/scenario tests that drive the Electron main
process. The specs' full text is in git history at that commit (`git show c6723c4:e2e/<file>`).

Status values:

- **ported**: a green Rust test pins the backend half of the scenario.
- **renderer, moves with phase 6**: the assertion is about pixels, DOM, focus, axe or window chrome; it moves with
  the renderer into `apps/desktop` (Tauri) and is checked by the renderer suite (`e2e-tauri/`). Not dropped.
- **Mac-only**: needs macOS (TCC, Keychain, WKWebView, real capture); listed in docs/mac-verify.md.
- **needs production change**: the Rust test exists as `#[ignore = "needs: …"]`; the exact change is in the
  "Production changes" section.
- **pending**: not ported yet (in progress).

Scenarios that split (backend + renderer) have one row per half.
