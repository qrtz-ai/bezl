# Changelog

## Unreleased

- **echo comes built in (ADR 0174):** qrtz.app includes echo again, so dictation works on a fresh install without the marketplace. echo is in the sidebar with an on/off switch in its view; turning it on asks once to download its speech model, Parakeet (about 460 MB, straight from Hugging Face and checked against the fingerprint built into qrtz). nano, ctrl and snap still install from the marketplace.
- **qrtz starts empty (ADR 0169):** the app no longer contains echo, nano, ctrl or snap. Install the ones you want from the marketplace; each module comes with its models in the same step (one yes, one progress bar, and nothing half-installed if a download fails). Removing a module also removes its models, unless another installed module uses them. The sidebar lists only what you installed. qrtz.app is about half the size. Until modules.qrtz.ai is live the marketplace says "coming soon".
- **Models download straight from Hugging Face (ADR 0171):** a module's models come from Hugging Face at a fixed version, and qrtz checks every file against the hashes in the signed package index before using it (a file that doesn't match is refused; interrupted downloads resume). modules.qrtz.ai serves only the modules and the index.
- **Downloaded modules are checked offline (ADR 0170):** every module's code is notarized by Apple before it's published, and qrtz checks the signature, the team, the file hashes and the notarized code hash on your Mac without asking Gatekeeper online.
- **"used by" tells the truth (marketplace → installed → shared):** the speech models now say which module uses them (Parakeet: echo; Nemotron, the speaker model and echo cancellation: nano) instead of "used by nothing", and "clean up" appears only when there is really something to delete, with its size. The label, `qrtz ls` and clean up now share one answer from the host, so they can't disagree, and clean up never touches a model an installed module needs.
- **A new look for every letter:** qrtz now draws everything in Geist Pixel Square instead of Geist Pixel Circle: the app, every module's view, and echo's pill. Same sizes and spacing, so nothing moves; the font is still bundled, so nothing downloads.
- **No more setup screens (ADR 0163):** qrtz opens straight to its views. Nothing downloads until you ask: press download in settings → speech, or switch echo or nano on in marketplace → installed (that switch is your yes). The module manager now shows each module's permissions beside its switch with an "allow" button, and macOS asks for the rest the first time a feature needs them. Old settings files load as before.
- **Speech models download per extension (audit P0-3):** qrtz now fetches only the models the extensions you use need: echo needs Parakeet (about 460 MB), nano needs Nemotron, the speaker model and echo cancellation. Before, the first download pulled all of them (about 1.31 GB). Model files also go straight to their pinned source while qrtz's own package hosts aren't set up, instead of trying two hosts that don't exist first.
- **Export diagnostics and check for updates (settings → system):** "export diagnostics" saves your logs plus macOS's crash reports for qrtz and its helpers into one file you can send us; it reads only files on your Mac. "check for updates" asks the signed package index for a newer qrtz, only when you press it, and installs nothing.
- **Signed releases:** `scripts/release/sign-notarize.sh` signs qrtz, its `qrtz` command and helpers with a Developer ID, notarizes and staples the app and the dmg (docs/release.md).
- **Hygiene:** `zip` 9.0.5 (RUSTSEC-2026-0367/0368/0369); FluidAudio pinned exactly at 0.17.7 with a committed `Package.resolved`, enforced by the Swift lint.

- **echo hears you better in noisy rooms (ADR 0115):** the microphone's audio is now converted to the rate the recogniser uses with a proper filter, so fan noise, hiss and sharp "s" sounds no longer fold into the speech it listens to.
- **echo now hears you with Parakeet:** echo's speech recognition is now Parakeet TDT v2 (English, on the Neural Engine), which makes fewer mistakes on full sentences. While you hold fn, echo transcribes each phrase as you pause, so letting go only has to finish the last one. It's a one-time download of about 460 MB from settings → speech. Until then echo uses Apple's on-device speech on macOS 26. Meetings keep their own recogniser, and it now loads only for a recording.
- **echo catches your first word (ADR 0104):** pressing fn now opens the microphone right away, so the words you start saying while echo gets ready are kept. The mic indicator lights at the press, as before, and goes out after the dictation; the mic is not kept open between dictations.
- **Pasted text lands faster:** when echo has to paste, it reports the text as inserted as soon as it's pasted, and puts your clipboard back a moment later in the background (also when you dictate twice in a row).
- **Changing "ignore the speakers" mid-dictation no longer changes the dictation that is running (N158).**
- **Switching microphones mid-sentence no longer cuts echo or a meeting off (N138):** when AirPods connect or drop, or you pick another input, qrtz carries on with the new microphone. Your dictation keeps the words from both sides of the switch. If no microphone comes back, echo inserts what it heard, and a meeting carries on with system audio and notes that the mic was lost.
- **echo keeps your last words when the Mac is busy (N139):** if speech recognition is running slowly when you release fn (for example during a meeting recording), echo now waits for it within its usual time limit and inserts the full text, instead of the shorter preview.
- **A setting for echo's speaker filter (ADR 0097):** settings → talk → "ignore the speakers" (on by default). It only acts when the Mac plays through its speakers, not on headphones. While it listens to the speakers, macOS may show its audio recording indicator for the length of the dictation. Turn it off to keep the raw mic.
- **A meeting that just stopped no longer shows as recording in a newly opened window (N155).**
- **echo's pill stays up for a press made while the last sentence is still being finished (N151).**
- **echo's pill keeps up with quick dictations (N145–N147):** dictating your next sentence while the last one is still being typed keeps the pill (and its waveform) on screen; a press echo can't start tells you every time instead of leaving "processing" up; the pill no longer disappears while echo's speech model loads at launch; and with auto-insert off it ends as soon as the text is ready.
- **echo no longer types what your speakers play (N143):** without headphones, a video or a call playing on the Mac used to end up in your dictation. echo now holds the mic down whenever it only hears the speakers, and your own words pass at full volume, even over a loud video. During a meeting it uses the meeting's system audio; otherwise it listens to the system audio for just the length of the dictation (only if qrtz already has the screen & system audio recording permission).
- **echo says "copied to clipboard" instead of an error:** when echo can't type into the app and puts the text on the clipboard, the pill now says so as a note, not as a failure. Turning the pill off in settings is respected by the native pill; failures then come as a notification.
- **echo's pill appears the moment you press fn:** the pill is now drawn natively by qrtz's helper instead of a web window. It shows at the press (even the first one after launch), on every Space and over full-screen apps, on the screen you're working on. It looks the same: a moving waveform, never your words.

- **echo is ready from launch:** qrtz loads echo's speech recogniser when it starts (if the speech models are downloaded) and keeps it loaded, so the first fn press doesn't wait for a model load. A press during that load uses it instead of loading a second copy. This keeps about 62 MB in memory while qrtz runs. Meeting models still load only for a recording.
- **echo's popup is just a moving waveform:** it no longer shows your words while you talk. The wave follows your voice live and settles into a slow swell while echo finishes; errors still show in the popup. The popup is narrower (240 px).
- **A meeting that starts during the post-download warm-up no longer compiles the speaker model twice (N137):** it waits for the warm-up's load and then uses the compiled model, so only one copy is in memory.
- **echo always answers after you release fn (N131), and says so when it can't listen (N134):** a stuck speech recogniser can no longer hold the release open; echo inserts what it had shown. When no recogniser is ready, pressing fn now says "speech recognition isn't ready yet" right away instead of recording nothing.
- **Playing a long meeting uses far less memory:** a recording is sent to the player a few MB at a time instead of all at once (a 2-hour meeting was about 230 MB).
- **Starting a recording stops the post-download model warm-up (N127)**, so no extra speech model stays loaded during the meeting.
- **A stood-down speaker channel is no longer silent (N126, protocol):** when speaker labelling stops for a channel (too far behind, or its model didn't load), the helper sends the turn it had open and a `diarization.unavailable {source, atMs, reason}` line.
- **Back-to-back meetings keep their speaker labels (N125):** a meeting that starts while the previous one's speaker model is still busy no longer loses speaker labels for the whole meeting.
- **echo no longer cuts off your last words:** after you release fn, echo keeps listening for a moment (50 ms plus the microphone's last block) and finishes the last word before inserting. If recognition falls far behind, echo waits for it instead of inserting a cut-short text.
- **Speaker labels from the first recording:** right after the speech models download, qrtz prepares them once, so the first recording doesn't spend a minute preparing the speaker model. On by default ("get speech ready right after download" in settings → speech).
- **Stopping a recording no longer waits for a slow speaker model (N121):** if speaker labelling falls more than 30 s behind, it stops for that channel (labels so far stay), and stop waits for it at most 3 s.

## 0.2.0 (2026-10-17)

### Highlights

- **One native app:** qrtz is now a single Tauri 2 app with a Rust core. Electron is gone, and it uses about 240 MB less memory.
- **Entirely offline:** no cloud speech, no cloud summaries, no API keys and no key storage. The only network use is downloading the signed speech models.
- **New names:** dictation is **echo** and the meeting recorder is **nano**.
- **On-device Nemotron with speaker labels:** nano transcribes your mic and the call separately with Nemotron 0.6B and labels who spoke. echo uses Nemotron too, without speaker labels, to stay fast.
- **Apple Intelligence summaries:** meeting summaries, action items and Q&A are written on your Mac by Apple's on-device model, including meetings longer than 4 hours.
- **Globe key fix:** holding fn for echo no longer switches your input language. You can turn this off in settings.
- **echo is faster:** there's no AI cleanup step, and the popup stays up until your text is inserted.
- **Chat removed:** the "ask" feature and its search model are gone. Search still uses full-text matching.
- **bun:** `bun install && bun start`.

### Details

#### Tauri only

- **Speaker labels on the Mac (ADR 0079):** recordings are transcribed with Nemotron (on-device) per channel, your mic and the call separately, and each channel is diarized, so the transcript says who spoke ("me", "speaker 1", or the call's names). Talk uses Nemotron too, without speaker labels, and stays loaded for a fast first press. The models (about 845 MB) download in onboarding or settings → speech, with progress, pause and resume; nothing downloads on first use anymore. Parakeet is gone, echo cancellation uses the downloaded model (or the echo gate without it), and the Apple speech backup is used only if macOS already has its assets.
- **Talk fix:** pressing fn did nothing after the globe-key change. The globe blocker no longer reports the key itself; a separate listen-only watch does, like before, so blocking the globe action can't break push-to-talk. If qrtz can't watch the push key, it now says so instead of staying silent.
- **Talk pill:** stays up after you let go of the key while the text is finished and inserted, and hides once it's in (or after a brief error flash).
- **GitHub Actions (docs/ci.md):** every push to main runs lint, typecheck, vitest, the renderer Playwright suite, cargo fmt, clippy and cargo test on Linux, plus the Swift helper tests and a desktop-crate check on macOS. A `v*` tag builds the Apple Silicon app (.dmg and zipped .app, unsigned for now) and publishes a GitHub release with the CHANGELOG section as notes.
- **qrtz is entirely offline (Jared's decision, ADR 0076):**
  - ElevenLabs is gone. Talk is on-device only, and if speech is missing or withdrawn, talk and note say they're unavailable instead of using the cloud.
  - OpenRouter and the other summary providers are gone. Summaries are Apple Intelligence on your Mac (ADR 0075).
  - Removed from settings: the speech engine, "fall back to on-device", the summary provider, model and API key, and "local only" (everything is local now).
  - Onboarding has no key step.
  - Saved ElevenLabs, OpenRouter and other cloud keys are deleted at the next launch. qrtz has no key storage at all now (ADR 0078).
  - Old settings files load and keep everything else.
  - The only network use left is downloading signed speech updates.
- **Talk:** if an earlier dictation couldn't be inserted while you were already dictating again, qrtz now tells you once you let go.
- **Summaries:** meetings over about 4 hours now get an on-device summary, and a retry picks up where it stopped. A helper restart mid-summary no longer costs the summary. A bad answer from the model fails at once instead of after 3 minutes.
- **Speech updates:** qrtz no longer checks for a speech update when you open onboarding or settings. Use "check for updates" in settings › speech. The unused "check for updates" app toggle and the crash-report setting are gone.
- **Keys:** a damaged keys file is reported instead of being read as empty, and saving a key no longer overwrites it.
- **Summaries are written on your Mac, offline (Jared's decision, ADR 0075):** Apple Intelligence's on-device model (macOS 26+) writes every meeting summary through the helper; nothing goes to OpenRouter or any other service. Long meetings are summarized in parts and merged (the model reads about 4,000 tokens at a time; a 5,000-word meeting takes about 2 minutes on an M1 Pro). If Apple Intelligence is off, still downloading, or not available on this Mac, the meeting keeps the transcript-based summary and says what to do ("turn it on in system settings › apple intelligence & siri, then retry"), with a retry button. The summary source reads "on-device · apple intelligence".
- **The "ask" chat is gone (Jared's decision, ADR 0072):** no more chat per meeting or across meetings, and no on-device search model (MiniLM) download, background indexing or their two settings. Search is full-text, as it always was underneath. Old settings files and databases load as before; a downloaded search model stays on disk unused.
- **fn for talk no longer switches the input language (macOS):** while fn is the talk key, the helper's session event tap swallows the Fn/globe events, so macOS doesn't also run its globe action (input source, emoji picker). It's on by default and can be turned off in settings → talk ("fn only for talk", `talk.blockGlobeKey`). It needs Accessibility; with only Input Monitoring, talk still works and the globe action runs as before.
- **Deepgram removed (Jared's decision):** ElevenLabs is the only cloud speech option. The Deepgram engine, its settings option, the `asr.deepgram` secret name and the contract value are gone. A config that picked Deepgram loads as `auto` (on-device) and keeps every other talk setting. A Deepgram dictation in the history keeps its text and shows as `elevenlabs`. A saved Deepgram key is deleted from the keychain (or the secrets file) at the next launch.
- **First run and speech setup in the Tauri app:** a short walkthrough (welcome, permissions, the speech download with pause, resume and retry, which keeps going in the background and survives a quit, and an optional OpenRouter key). Settings gained a speech section (update, re-download, delete, auto-update, and the search model). Note and talk say when speech is missing or still downloading. A search model downloaded while the app runs is used without a restart (ADR 0064). Plain-http downloads are allowed only to a real loopback host (N100).
- **About 240 MB less memory (ADR 0066):** jsonschema 0.33 → 0.59. The IPC contract validators took 222 MB in 0.33 and take 2 MB in 0.59. The Tauri app now uses 362 MB PSS idle and 485 MB recording on Linux (it was 601 and 726).
- **Electron is gone (ADR 0061):** qrtz is one Tauri 2 app with the Rust core. `apps/desktop` is the Tauri app (the renderer and sub-app manifests moved in); the Electron main process, worker, Forge packaging, Electron e2e suite and its scripts are deleted (last at `c6723c4`). Rust is the oracle for the shared vectors and scenarios under `spec/`. Libraries, backups and `talk.json` from the Electron build open unchanged.
- **Live transcript from the speech module in recordings (step 9, ADR 0046 §9.4):** each recording part runs its own module session attached to the helper's capture; its words are the live transcript, and without an installed module the part records audio and shows speech unavailable.
- **Chat never sees a meeting pending delete (N90/N93, ADR 0060).**
- **Talk has no AI cleanup (Jared, for speed):** no OpenRouter call. The text goes in as soon as the key is released, cleaned by the on-device rules only (fillers, punctuation, the dictionary). The `ai cleanup` toggle and `talk.aiCleanup` / `cleanupModel` / `cleanupTimeoutMs` are gone, and old configs that have them still load. Haiku stays for note summaries.
- **The talk pill goes the instant you release the key:** the final text and the insert finish in the background. A failure (for example nothing could insert, so the text went to the clipboard) briefly shows the pill again with the error, or posts a notification when the pill is off.
- **bun replaces npm:** `bun install && bun start`. `bun.lock`, bun workspaces; no separate Node needed.

#### helper mux + TCC revocation (H5/H6)

- **Speakers per channel in recordings (Bozniak; ADR 0058 §12):** with the speech module, mic and system audio are diarized apart, and each line keeps its channel's speaker id (`mic:0`, `system:1`). The mic's main voice is "me" by default and can be renamed; another voice on the same mic is its own speaker, never folded into "me", and a mic line with no diarized voice gets no speaker. Everyone else is "speaker n" in order of first appearance; meeting-app (AX) names still name system speakers, never the mic. A rename survives a finalize retry. Meetings without diarization keep the AX-only names as before. No migration.

- **Dictation in the Rust core (`crates/qrtz-talk`, Bozniak; ADR 0058):** the port of `TalkService` behind qrtz-app's `TalkPort`, built on `qrtz_speech::SpeechEngine` (ADR 0046) with no model named. On-device is the default; ElevenLabs is opt-in and runs in the host. With auto-failover on, a dropped or unreachable cloud falls back to on-device like Electron; with it off, the dictation ends with a typed `offline` error and the heard text on the clipboard. Talk starts the speech session before the mic opens and refuses when the module doesn't fit this app (`speech-incompatible`) or isn't ready (`speech-unavailable`), without reading or showing any engine metadata, checks every module event again (bounds, channels, times), and ends with the heard text when the module goes away: `speech-lost` for a crash, `speech-unavailable` when it was revoked, went stale or isn't installed. A version revoked while the revocation list is expired is never rolled back: talk uses the user's enabled cloud engine or says speech is unavailable, and a running session ends at its next safe point. `talk.json` keeps the Electron format, owner-only and atomic; a corrupt file is moved aside and a full disk leaves the old file. Recording sessions take `SpeechEvent`s too (`NoteRuntime::speech_event`, N37/N42; words on a channel the session doesn't have are dropped, N68), with a new reducer event `speech-ready` (TS and Rust, vector 19). `TalkView.errorKind` is on the wire (zod, contracts). Shared vectors `spec/vectors/talk/*`; scenarios `spec/scenarios/lifecycle-speech/`. qrtz-app wiring: rust-core-api.md §11.

- **Chat answers questions asked in Chinese, Japanese or Thai (Bozniak cycle 14, N49; ADR 0047):** "我们决定了什么" now finds "我们决定推迟发布。" across meetings, with or without an embedding model. Question words in scripts written without spaces are cut into character bigrams (at most 16) and matched inside transcript lines, in retrieval (TS and Rust, shared SQL) and in the ranker; other words still use the index, and questions without such a word run as before. Chat words keep combining marks, so Thai and Hindi words stay whole. TS and Rust share `spec/stress/chat-cjk.json`. No migration.

- **Search finds Chinese, Japanese and Thai words anywhere in a line (Bozniak cycle 12, N48; ADR 0039):** "会议" in "明天的会议很重要", "金曜日" in "会議は金曜日です" and "ประชุม" in "เริ่มประชุมกันเลย" now match in meeting search and the list filter, in transcripts, titles and summaries. Words in scripts written without spaces are matched as substrings; every other word still uses the FTS index, and searches without such a word run exactly as before. TS and Rust share `spec/stress/fts-substring.json`. No migration. Still open: chat questions in Chinese or Japanese (N49).

- **Search finds words with apostrophes (Bozniak cycle 11, N46/N47; ADR 0038):** "don't", "O'Reilly", "l'équipe" and possessives ("Jared's" finds "Jared") now match in meeting search, the list filter and chat. Each word goes to SQLite FTS5 as a quoted phrase, so it is split by the same tokenizer as the index; Hindi and Thai words stay one phrase. Chat no longer drops the line it found for such a question. TS and Rust share `spec/stress/fts-queries.json`. No migration. Still open: a Chinese, Japanese or Thai word inside a longer run of text is not found (N48).

- **Reconnect offsets ignore a wall-clock jump (Bozniak cycle 10, N45; ADR 0037):** `helper-lost` / `helper-restored` stamps come from a monotonic clock (`performance.now()` / `Clock::mono_ms`), so a laptop sleep or NTP step during a reconnect no longer slides the next part's transcript while the WAV pad stays capped at 35 s. Wall clock still owns `startedAt` / `stoppedAt` / live elapsed. Scenario `H7-clock-jump-during-reconnect` now expects a meeting-length file; `N45-multi-reconnect-clock-jump` covers two jumps. No migration, no protocol change.

- **Audio and transcript line up after a reconnect (Bozniak cycle 9, H7/N44; ADR 0032):** finalize pads each helper-restart gap with silence, from the part offsets the session now keeps (`partOffsetsMs`, on the session and the pipeline context), so seeking to a transcript line plays that moment. One gap is padded at most 35 s. The stitch streams in 1 MiB chunks instead of loading every part. TS and Rust share `spec/stress/stitch-gaps.json`. Rows from older builds have no offsets and stitch end to end as before. No migration.
- **A crash during finalize never doubles the audio (N41; ADR 0033):** the stitch commits to `<main>.stitched` before it removes the parts, and a retry that finds it only finishes. Delete removes a leftover `.stitched`.
- **A reconnect that brings audio back is not "no audio" any more (N42; ADR 0034):** "no audio" / "no transcription" reported by a helper at its start end with that helper. The new helper's own reports apply to its part, so the summary keeps the rest of the meeting.
- **Speaker names after a reconnect use the new part's clock (N43; ADR 0035):** an active-speaker event in the same chunk as the start ack waits for it, and one before the first ack is ignored.
- **The meeting notice says when a source was not recorded (ADR 0036):** "mic not recorded 10:12–10:20", "system audio not recorded after 10:50", or "nothing recorded …", from the saved lost stretches (Electron UI, mapping only).

- **A lost mic is on the meeting record (Bozniak cycle 8, N39/N40; ADR 0031):** when the mic (or system audio) is lost to a revoke, a device failure or no source left, the session and the meeting keep the stretch (`lostSpans`), and it ends at the reconnect that brings the source back, or at the stop. The summary counts it as that source's silence, so a revoked mic plus quiet system audio is "no audio at all" instead of a one-sided gap that told the model the user's speech there was real. A recording started with the mic denied now flags "No mic" (like "Mic only" for a denied screen), so the record knows too. TS `NoteService` and Rust `NoteRuntime`, vector 14, scenario `N39-mic-lost-system-silent`. No migration.

- **Capture device failure on the host (N35; ADR 0028):** `capture.degraded{no-mic}` is applied like a revoke, but only while recording and only for flags not already set. A reconnect clears it (`deviceLost`), unless a revoke of the same flag took it over. The mic's silent stretch closes, later mic silence is ignored, and system silence then shows "No sound". The meeting keeps `capture.deviceFailures`, apart from revokes, and the meeting notice says "mic device failed at hh:mm". TS `NoteService` and Rust `NoteRuntime`, vectors 12–13, four `N35-*` scenarios, and the mocks `micFails` / `QRTZ_MOCK_MIC_FAILS` (TS and Rust).
- **`capture.degraded` on the wire (N35, protocol only):** `{degraded: RevocationDegradation[] (≥1, only `no-mic` today), reason ≤ 200}`, for a source that lost its in-source mic and records the rest. Zod, contracts, Swift encode (reason cut on whole scalars) and decode, golden fixtures (2 valid, 4 invalid). Rules pinned in docs/helper-protocol.md: sticky until a reconnect like N4 (no `capture.restored` yet); `no-mic` closes an open mic silence stretch and counts the mic as not delivering for `noAudio`, and a later `capture.silent{mic}` is ignored. The helper sends it when the tap's or SCK's in-source mic fails to start (instead of a stderr-only line), through the controller (`AudioSource.start(onBlock:onDegraded:)`): after `recording.started`, once per flag per recording, never after stop/abort, dropped for a source that then fails. The host reducers do not apply it yet.
- **No-audio UI (N29, H8, Electron):** while recording, `CaptureStatus` shows a badge per silent source ("no audio from mic since 10:04" / "from system audio"), replaced by a stronger "no audio is being recorded" when `noAudio` is on. A finished meeting shows a `CaptureNotice` built from the saved `pipeline.capture`: one line per silent stretch ("no audio from mic 10:04–10:09") and per source fallback ("meeting audio tap failed, used screen capture", repeats as ×n, capped with "+n more"). When `noAudio` turns on and no qrtz window is focused, the host raises an OS notification (`NoteService` `onNoAudio`, once per silent stretch), behind the new setting `note.notifyNoAudio` ("warn when no audio", on by default). These badges replace the N32 "No sound" chips (`captureChips` became `liveCaptureStatus`, same rules: none on top of `audio-unavailable`). E2E `capture.spec` drives `QRTZ_MOCK_SILENT`.
- **Silence shows live, and summaries keep one-sided stretches (Bozniak cycle 6, N32/N34; ADR 0026):** the capture status shows "No sound from mic" / "No sound from system audio" while a source is silent, or "No sound" when every delivered source is. The chip clears when sound returns. In the summary prompt, only a stretch with no audio at all gets the "never summarize" rule. A stretch where one source was silent (most often the user presenting while the others are quiet) keeps its transcript.
- **Secrets survive a full disk (Bozniak cycle 6, N33/N30; ADR 0027):** `secrets.json` is written to a fresh owner-only `.tmp` and renamed. Before, it was rewritten in place, and a failed write could erase every saved API key. It's now also 0600 when an older build left it 0644.
- **Silent input and capture fallbacks on the meeting (N29, H8 host side; ADR 0025):** a silent capture source shows live on the session (`silent [{source, sinceMs}]`, `noAudio` when nothing is delivered). Audible clears it, unlike the sticky permission flags. Silent stretches and capture fallbacks are kept on the meeting (`PipelineState.capture`, via `note:pipeline`). The summary prompt lists silent gaps of 60 s or more so the model does not invent content for them. `capture.fallback{to: null}` degrades `audio-unavailable` at once. TS `NoteService` and Rust `NoteRuntime`, shared vectors and scenarios, and Rust mock helper knobs `QRTZ_MOCK_SILENT=system@…` and `QRTZ_MOCK_FALLBACK`. No migration.
- **Silent capture on the wire (N29, protocol + helper):** while recording, the helper tracks the system and mic channels apart and sends `capture.silent {source: 'system'|'mic', sinceMs}` after 60 s under ≈ −70 dBFS (`SilenceConfig.default` / `CAPTURE_SILENCE`, configurable via `HelperDeps.silence`) and `capture.audible {source}` when sound returns. Zod, Swift, contracts, golden fixtures (3 valid, 4 invalid), mock helper `silence` option and `QRTZ_MOCK_SILENT`. The host only logs it for now; the `silent-input` degradation comes with the reducer.
- **Structured capture fallback (H8):** when an audio source fails to start, the helper sends `capture.fallback {from, to, reason}` (`to: null` when no source is left) instead of a free-text log line. The host logs it as a warning like before. Zod, Swift, contracts, golden fixtures (2 valid, 2 invalid), mock helper option `captureFallback`.
- **Tauri data dirs owner-only (N25 parity):** `qrtz-app` creates the app data dir and the recordings dir 0700 (`AppDirs::prepare`, `private_dir`: `DirBuilderExt::mode(0o700)` plus a chmod for a directory an older build made 0755), and the config store uses it for its directory. Tested under umask 022.
- **Concurrent recording + dictation (mux):** a dictation runs during a meeting recording and both read the mic through one shared tap (`MicHub`). Each kind is single-instance (duplicate starts are ignored, not queued), and `dictation.start` is refused when the mic is denied. Spec: `docs/helper-protocol.md`, ADR 0004.
- **Permission revoked mid-capture:** the helper polls TCC while capturing and emits `permission.revoked`. Recordings degrade live (new `no-mic` flag, plus `mic-only`, `audio-unavailable` and `ax-unavailable`) and keep running. Dictation stops gracefully, keeping and inserting what was heard. Onboarding no longer covers a running recording.
- **Arbiter wiring fixes (review of 91d11bb):** the arbiter is now enforcing (the helper performs every mic effect, on commands too) and models the warm mic, so a warm mic no longer goes deaf after a revoke and re-grant. Ignored starts answer `error{recording.busy | dictation.busy}`. `recording.stop` takes an optional `audioPath`, so a late stale ack can't stop the real recording. `MicHub` stops a device whose start raced the last unsubscribe. A recording started with the mic denied never opens it. `helperLost` releases every reader. TCC is polled while the mic is warm.
- **Busy errors name both sessions (re-review of fe704d0):** `dictation.busy` carries `{id, activeId}` and `recording.busy` carries `{audioPath, activeAudioPath}`. The host acts only on the busy for its start in flight, never cancels by its current id when the busy names another, keeps a duplicate start of a running session, and cancels/stops an orphaned active session it doesn't know before failing, so a helper still running d1 after a host reload, or an orphaned recording A, no longer locks out every retry. The busy refusal is tied to one attempt's file. `MicHub`: readers that join an in-flight device start wait for it and rethrow its error (and are detached) if it fails.
- **A recording never runs without a file (Bozniak, pathless-recording edge):** the arbiter tracks `activeAudioPath` and asserts `recording` iff it is set, in TS and Swift. A start without a path is refused. When the WAV can't be created the helper fails closed: the new `recordingFileFailed` arbiter event tears the recording down (`recording.lost`, the mic reader and permit released, no `recording.started`) and the helper answers `error{recording.file, audioPath}`; a dictation running alongside keeps going. The host (TS `NoteService` and Rust `NoteRuntime`) fails that start at once as `recording-file`. A `recording.busy` naming no active file is a broken invariant: the host logs it as a bug, sends no stop, and restarts the helper as a last-resort watchdog. No pathless stop was added. Vectors: 2 shared, 3 edge; scenarios `F5-recording-file`, `F5-busy-no-active-file`.
- **Talk survives a helper restart (Bozniak cycle 2, T1):** `TalkService` has a helper-lost path. A `hello` from a newer helper, or the supervisor going down, while a dictation is active ends it through the same graceful path as a helper-ended dictation (reason `helper-lost`: the view leaves `listening`, waiters resolve, the error says the capture helper restarted). The pinned `it.fails` test now passes as a normal test.
- **Scoped abort before a restart (Bozniak cycle 2, N2):** on a missed `recording.stop` ack the host (TS `NoteService` and Rust `NoteRuntime`) first sends `recording.abort{audioPath}` with a hard 2 s deadline (`abortAckMs`). The helper handles it out of band, tears down only that file's writer without the wedged flush, and always answers `recording.aborted{audioPath}`, so a dictation on the shared helper survives. The helper is restarted only when the abort also times out. Protocol (zod, Swift, contracts, golden fixtures), arbiter `{cmd: "recording.abort"}` (1 shared, 1 edge vector, Rust port), scenarios `F6-stop-ack-abort` / `F6-stop-ack-timeout`, mock helpers.
- **Tauri talk hooks (Bozniak cycle 3, T2):** `qrtz-app` routes `hello` to both the recording runtime and the talk port, and `TalkPort::helper_status` (default no-op) receives every supervisor status, so the Rust talk service can run the T1 helper-lost path when it lands.
- **Deleting a meeting deletes it (Bozniak cycle 4, N14–N18, T3):** delete removes the recording and any leftover `<id>.p<n>.wav` (only inside the recordings folder; a path from the DB outside it is never touched). The host stops that meeting's post-processing at once (no retries, fallback or index for a deleted meeting; the session lets go of it), and a relaunch after quitting inside the undo window no longer resumes the deleted meeting's summary. The recordings folder is 0700 and talk history 0600. TS `NoteService.deleteMeeting` = Rust `NoteRuntime::delete_meeting`. ADRs 0015, 0016.
- **Safer at the edges (Bozniak cycle 4, N19–N21):** a database from a newer qrtz is refused before anything is written to it (no WAL switch, bytes unchanged). Three note IPC channels now bound their ids like the rest. The long-meeting prompt cut never splits an emoji. ADRs 0017–0019.
- **Deleting the live meeting is refused (cycle 4 follow-up):** the host (Electron `NoteService`, also for an undoable `deferMs` delete, and the Rust `NoteRuntime`) refuses to delete the meeting that is starting, recording, reconnecting or stopping, with E_VALIDATION "This meeting is still recording. Stop the recording, then delete it." Nothing is removed and the recording goes on. Scenario `N24-delete-while-recording` (TS + Rust).
- **Tauri `note:delete`:** `qrtz-app` routes it to the runtime (`NoteRuntimePort`, feature `runtime`, onto `NoteRuntime::delete_meeting`) and emits `note:changed` after it; the response stays `{ok: true}`, no contract change. `pending_delete` stays `None`.
- **Revocation degradations come from the helper (N4):** `permission.revoked` carries `degraded`, the helper arbiter's own `degrade:*` effects (`[]` when not recording). The host (Electron `NoteService`, Rust `NoteRuntime`) applies that list and derives it from its own, possibly `unknown`, permission snapshot only when an older helper omits it. Zod (`RevocationDegradation`), Swift, contracts, golden fixtures (2 valid, 2 invalid), the TS mock, scenario `N4-revoked-carries-degraded`.
- **Your library stays yours on disk (Bozniak cycle 5, N25, N26, T4):** the database and the `-wal`/`-shm` SQLite keeps next to it are owner-only (0600) whatever the umask (TS `openDatabase` = Rust `Db::open`: the file is created 0600 before SQLite opens it, and files an older build left are tightened). The backup snapshot is created exclusively at 0600 in a private temp folder (a planted symlink is never followed), the backup zip is 0600, the Electron app data folder is 0700, and talk history and config stay 0600 even over a crash-left `.tmp`. ADR 0020.
- **Deleted while processing (Bozniak cycle 5, N27, N28):** a step still running when its meeting is deleted (a slow summary) now finds nothing when it returns: no retry, fallback, event or save. Before, the Electron host hit an unhandled error and the Rust host briefly brought the deleted pipeline back. A finalize that fails mid-stitch (disk full) no longer leaves a meeting-sized `.stitch` file behind, and delete removes one an older build left. Scenario `N27-deleted-mid-step` (TS + Rust). ADR 0021.
- **Long meetings are summarized end to end (Bozniak cycle 5, N21):** over the prompt budget, the transcript is sent as evenly spaced windows of whole lines across the meeting, with `[… a–b not shown …]` markers, instead of only its first and last half hour. It never exceeds the budget. ADR 0022. More delete coverage: scenario `N24-delete-refused-starting-reconnecting`, and ADR 0023 records the refuse-not-discard decision. ADR 0024 proposes WAV gap padding (H7).
- One pure arbiter in TS and Swift with shared vectors (`spec/vectors/helper/arbiter.json`). Mock helper: `QRTZ_MOCK_REVOKE="microphone@1500"`.

## v0.1.0 (2026-10-16)

First tagged build. Verified on Linux with the mock helper; macOS capture still needs on-device verification (see docs/mac-verify.md).

### Added

- **Shell:** Electron, React 19 and Vite, with lazy-loaded sub-apps (Home, Memo, Gallery, Settings), a command palette (⌘K), a menu bar item and capability-checked IPC with a zod contract.
- **Memo:** calendar-free Zoom/Meet detection through the Accessibility tree, a record prompt or "Always record", a live streaming transcript with AX speaker names, and a floating mini HUD (pause, notes, stop) with a ⌘⇧R shortcut.
- **Notes and summaries:** Granola-style timestamped live notes, and summaries with action items and Q&A in 5 templates. They use OpenRouter, Ollama, or the on-device extractive fallback.
- **Archive:** SQLite FTS5 search, semantic search (on-device MiniLM; native onnxruntime with a WASM fallback), chat per meeting or across meetings with citations, speaker rename and merge, Markdown export and Copy, and delete with a confirm dialog and an Undo that survives quitting.
- **Privacy:** pause capture (⌘⇧P), excluded apps, local-only mode and audio retention.
- **Backup and restore:** a streamed zip (yazl/yauzl) with a sha256 manifest and a progress bar. Import verifies everything and never overwrites.
- **Swift helper:** JSON-lines protocol (golden fixtures), AX scrapers for Zoom and Meet (11 fixtures), Core Audio and ScreenCaptureKit capture, FluidAudio ASR, diarization and echo cancellation.
- **Design system (`@qrtz/ui`):** tokens with a generated reference, dark (default), light and system themes, motion and focus tokens, and a component gallery. Every view is axe-clean in both themes.
- **Release tooling:** `scripts/release-mac.sh` (sign, notarize, staple), an optional self-hosted update feed (off by default), `npm run screenshots` and `scripts/fresh-clone-check.sh`.

### Reliability

- Helper crash recovery keeps the audio and transcript, an LLM failure falls back with Retry, and startup recovery finishes interrupted meetings.
- Cold start is about 0.65 s to home on Linux; a 2-hour meeting opens in about 0.2 s; a 400 MB backup runs in bounded memory.

### Security

- Context isolation, sandbox, strict CSP and Electron fuses. Secrets are stored only through safeStorage or `QRTZ_*` env vars, and dev-only env vars are stripped from packaged builds.
- `npm audit --omit=dev`: 0 vulnerabilities. Dev-only: vitest was upgraded to v5, and oxfmt was upgraded. One advisory remains in `image-size` through the macOS DMG maker (build time only, with no fix upstream).
