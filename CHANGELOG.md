# Changelog

## Unreleased: helper mux + TCC revocation (H5/H6)

- **Concurrent recording + dictation (mux):** a dictation runs during a meeting recording and both read the mic through one shared tap (`MicHub`). Each kind is single-instance (duplicate starts are ignored, not queued), and `dictation.start` is refused when the mic is denied. Spec: `docs/helper-protocol.md`, ADR 0004.
- **Permission revoked mid-capture:** the helper polls TCC while capturing and emits `permission.revoked`. Recordings degrade live (new `no-mic` flag, plus `mic-only`, `audio-unavailable` and `ax-unavailable`) and keep running. Dictation stops gracefully, keeping and inserting what was heard. Onboarding no longer covers a running recording.
- **Arbiter wiring fixes (review of 91d11bb):** the arbiter is now enforcing (the helper performs every mic effect, on commands too) and models the warm mic, so a warm mic no longer goes deaf after a revoke and re-grant. Ignored starts answer `error{recording.busy | dictation.busy}`. `recording.stop` takes an optional `audioPath`, so a late stale ack can't stop the real recording. `MicHub` stops a device whose start raced the last unsubscribe. A recording started with the mic denied never opens it. `helperLost` releases every reader. TCC is polled while the mic is warm.
- **Busy errors name both sessions (re-review of fe704d0):** `dictation.busy` carries `{id, activeId}` and `recording.busy` carries `{audioPath, activeAudioPath}`. The host acts only on the busy for its start in flight, never cancels by its current id when the busy names another, keeps a duplicate start of a running session, and cancels/stops an orphaned active session it doesn't know before failing, so a helper still running d1 after a host reload, or an orphaned recording A, no longer locks out every retry. The busy refusal is tied to one attempt's file. `MicHub`: readers that join an in-flight device start wait for it and rethrow its error (and are detached) if it fails.
- **A recording never runs without a file (Bozniak, pathless-recording edge):** the arbiter tracks `activeAudioPath` and asserts `recording` iff it is set, in TS and Swift. A start without a path is refused. When the WAV can't be created the helper fails closed: the new `recordingFileFailed` arbiter event tears the recording down (`recording.lost`, the mic reader and permit released, no `recording.started`) and the helper answers `error{recording.file, audioPath}`; a dictation running alongside keeps going. The host (TS `NoteService` and Rust `NoteRuntime`) fails that start at once as `recording-file`. A `recording.busy` naming no active file is a broken invariant: the host logs it as a bug, sends no stop, and restarts the helper as a last-resort watchdog. No pathless stop was added. Vectors: 2 shared, 3 edge; scenarios `F5-recording-file`, `F5-busy-no-active-file`.
- **Talk survives a helper restart (Bozniak cycle 2, T1):** `TalkService` has a helper-lost path. A `hello` from a newer helper, or the supervisor going down, while a dictation is active ends it through the same graceful path as a helper-ended dictation (reason `helper-lost`: the view leaves `listening`, waiters resolve, the error says the capture helper restarted). The pinned `it.fails` test now passes as a normal test.
- **Scoped abort before a restart (Bozniak cycle 2, N2):** on a missed `recording.stop` ack the host (TS `NoteService` and Rust `NoteRuntime`) first sends `recording.abort{audioPath}` with a hard 2 s deadline (`abortAckMs`). The helper handles it out of band, tears down only that file's writer without the wedged flush, and always answers `recording.aborted{audioPath}`, so a dictation on the shared helper survives. The helper is restarted only when the abort also times out. Protocol (zod, Swift, contracts, golden fixtures), arbiter `{cmd: "recording.abort"}` (1 shared, 1 edge vector, Rust port), scenarios `F6-stop-ack-abort` / `F6-stop-ack-timeout`, mock helpers.
- **Tauri talk hooks (Bozniak cycle 3, T2):** `qrtz-app` routes `hello` to both the recording runtime and the talk port, and `TalkPort::helper_status` (default no-op) receives every supervisor status, so the Rust talk service can run the T1 helper-lost path when it lands.
- **Deleting a meeting deletes it (Bozniak cycle 4, N14–N18, T3):** delete removes the recording and any leftover `<id>.p<n>.wav` (only inside the recordings folder; a path from the DB outside it is never touched). The host stops that meeting's post-processing at once (no retries, fallback or index for a deleted meeting; the session lets go of it), and a relaunch after quitting inside the undo window no longer resumes the deleted meeting's summary. The recordings folder is 0700 and talk history 0600. TS `NoteService.deleteMeeting` = Rust `NoteRuntime::delete_meeting`. ADRs 0015, 0016.
- **Safer at the edges (Bozniak cycle 4, N19–N21):** a database from a newer qrtz is refused before anything is written to it (no WAL switch, bytes unchanged). Three note IPC channels now bound their ids like the rest. The long-meeting prompt cut never splits an emoji. ADRs 0017–0019.
- One pure arbiter in TS and Swift with shared vectors (`spec/vectors/helper/arbiter.json`). Mock helper: `QRTZ_MOCK_REVOKE="microphone@1500"`.

## Unreleased: qrtz talk

- **qrtz talk (dictation):** a new `talk` tab. Hold fn (configurable) or press ⌘⇧Space to dictate into any app. A floating pill that never takes focus shows the mic level and streaming text. When you let go, the text is finalized, cleaned up and inserted.
- **Pluggable streaming ASR:** cloud WebSocket engines (ElevenLabs Scribe v2 Realtime, Deepgram Nova-3) are the primary when a key is saved in Settings (Keychain via safeStorage, never committed). The helper's on-device Parakeet stream always runs alongside, with automatic failover on socket error, a stalled stream, a late final or empty text. Settings → Talk → Speech engine (auto, ElevenLabs, Deepgram, on-device). Local-only privacy forces on-device.
- **Helper:** `dictation.*`, `insert.*` and `hotkey` protocol messages. The mic-only source has an optional warm mic and a pre-roll ring buffer, with its own recogniser instances so dictation works during a meeting. Insertion tries AX selected text, then an AX value splice, then pasteboard + Cmd-V and restores the clipboard. A native CGEvent-tap push-to-talk key monitor is included. Core logic is in `QrtzHelperCore/Dictation.swift` (tested on Linux); macOS pieces are in `mac/Talk.swift` [MAC-VERIFY].
- **Cleanup:** an OpenRouter pass with a timeout (900 ms default) falls back to on-device rules (fillers, stutters, spoken "new line", capitalization, punctuation) and the personal dictionary. If insertion fails, the text is left on the clipboard.
- **Latency:** each dictation records key-down → first partial, key-up → final, cleanup time and key-up → inserted (history meta and the `talk latency` log). Run `scripts/bench-talk-asr.mjs` to measure cloud engines with real keys.
- **Toggles:** dictation, fall back to on-device, warm mic, clean up text, AI cleanup, insert into app, restore clipboard, floating pill and keep history.
- Research and recommendation: `docs/research-talk.md`.

## Unreleased: redesign

- **One font:** Geist Pixel (Square, OFL-1.1, bundled locally) for everything, on a pixel-grid type scale (display, h1, h2, h3, bodyLg, body, bodySm, caption, label, mono, code; nothing below 13.158px). Typography lives only in `@qrtz/ui`, through `Text`, `Heading`, `Label`, `Code`/`Mono` and `Link`.
- **Layout:** the sidebar and Home dashboard are gone. Tiny bottom tabs (note, settings; gallery only in dev builds) sit under a full-window content area. Note has two panes: the meeting list with Record on the left, and the selected meeting on the right (transcript first; summary, notes and ask one tab away). Secondary actions are in a "more" menu, and search is behind a toggle and ⌘K.
- **Less text:** help blurbs, subtitles, hints and empty-state body copy are removed, and errors are one line.
- **Toggles:** every automatic behavior has its own switch: detect meetings, record automatically, ask to record, floating HUD, delete old recordings, summarize after meetings, index for search, menu bar icon (live), open at login and check for updates.
- **OpenRouter credits:** a 402 / no-credits error is shown as an error state with retry (the summary keeps its on-device extractive fallback). There is no automatic fallback to free models. There is also an opt-in live test (`QRTZ_TEST_OPENROUTER=1`).
- **Memo is now Note (qrtz note):** the sub app, tab (`note`), package (`packages/features/note`, `@qrtz/feature-note`), core module (`packages/core/src/note`), components (`NoteView`, `NoteService`, `NoteRepo`), IPC channels (`note:*`, worker `note.*`), capabilities (`note.read`/`note.record`/`note.write`), settings key (`config.note`) and test IDs (`note-*`, view root `note-app`) are renamed. Stored `config.json` files with a `memo` block are migrated to `note` on first launch and rewritten once. The database holds no sub-app names; the shipped migration label `2_memo` stays as is.
- **Icons:** every icon is a Feather icon (`react-feather` 2.0.10, MIT) through one `Icon` component in `@qrtz/ui` with size tokens (`tokens.icon`). All glyphs (■ ▶ ❚❚ ⌕ ↻ ✎ ☐ ● ◎ ⚙ ▦ …) are replaced, `check-ui-purity` blocks icon-library imports and glyph icons outside `packages/ui`, and the gallery has an Icons page.
- **Lifecycle merge:** the other worker's recording lifecycle (pipeline steps with retry, streaming partials, reconnect/degraded states) is integrated into the redesign: `StreamingTranscript`, `PipelineSteps` and `CaptureStatus` in `@qrtz/ui`, the live transcript shown in the meeting view, and the meeting view opening on Transcript. The summarize and index toggles skip their pipeline steps; a manual Summarize still runs.
- **Lint:** `check-typography.mjs` and `check-ui-purity.mjs` fail on raw typography, `style`/`className`, raw JSX elements, token styling or CSS outside `packages/ui`. Every new component has a gallery entry, and the gallery moved into `@qrtz/ui/gallery`.

## v0.1.0 (2026-10-16)

First tagged build. Verified on Linux with the mock helper; macOS capture still needs on-device verification (see docs/mac-verify.md).

### Added

- **Shell:** Electron, React 19 and Vite, with lazy-loaded sub-apps (Home, Memo, Gallery, Settings), a command palette (⌘K), a menu bar item and capability-checked IPC with a zod contract.
- **Memo:** calendar-free Zoom/Meet detection through the Accessibility tree, a record prompt or "Always record", a live streaming transcript with AX speaker names, and a floating mini HUD (pause, notes, stop) with a ⌘⇧R shortcut.
- **Notes and summaries:** Granola-style timestamped live notes, and summaries with action items and Q&A in 5 templates. They use OpenRouter, Ollama, or the on-device extractive fallback.
- **Archive:** SQLite FTS5 search, semantic search (on-device MiniLM; native onnxruntime with a WASM fallback), chat per meeting or across meetings with citations, speaker rename and merge, Markdown export and Copy, and delete with a confirm dialog and an Undo that survives quitting.
- **Privacy:** pause capture (⌘⇧P), excluded apps, local-only mode and audio retention.
- **Backup and restore:** a streamed zip (yazl/yauzl) with a sha256 manifest and a progress bar. Import verifies everything and never overwrites.
- **Swift helper:** JSON-lines protocol (golden fixtures), AX scrapers for Zoom and Meet (11 fixtures), Core Audio and ScreenCaptureKit capture, FluidAudio ASR, diarization and echo cancellation.
- **Design system (`@qrtz/ui`):** tokens with a generated reference, dark (default), light and system themes, motion and focus tokens, and a component gallery. Every view is axe-clean in both themes.
- **Release tooling:** `scripts/release-mac.sh` (sign, notarize, staple), an optional self-hosted update feed (off by default), `npm run screenshots` and `scripts/fresh-clone-check.sh`.

### Reliability

- Helper crash recovery keeps the audio and transcript, an LLM failure falls back with Retry, and startup recovery finishes interrupted meetings.
- Cold start is about 0.65 s to home on Linux; a 2-hour meeting opens in about 0.2 s; a 400 MB backup runs in bounded memory.

### Security

- Context isolation, sandbox, strict CSP and Electron fuses. Secrets are stored only through safeStorage or `QRTZ_*` env vars, and dev-only env vars are stripped from packaged builds.
- `npm audit --omit=dev`: 0 vulnerabilities. Dev-only: vitest was upgraded to v5, and oxfmt was upgraded. One advisory remains in `image-size` through the macOS DMG maker (build time only, with no fix upstream).
